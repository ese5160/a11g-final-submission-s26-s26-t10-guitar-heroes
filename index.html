FretNought

A wireless smart guitar learning system using sensor fusion to confirm strums and guide chord progressions in real time.

01

Overview

FretNought is a smart guitar learning system that places addressable LED strips beneath the strings of an acoustic guitar to display chord shapes directly on the fretboard. A wireless wrist-worn pick contains an IMU that detects strum motion, while a microphone on the fret device captures the resulting audio. Both signals are streamed over Wi-Fi to a Node-RED backend, which fuses the events to confirm a real strum before advancing the chord progression.

The system supports two modes. In Practice mode, the user selects chords manually and a confirmed strum advances to the next chord. In Performance mode, chords advance automatically based on a user-defined tempo and capo position, allowing playback of full progressions. The backend also exposes a web dashboard for chord input, mode selection, and live system state.

02

Architecture

The system consists of three independent components communicating over Wi-Fi and MQTT. Two SiWx917 Wi-Fi MCUs handle the embedded side, one mounted on the fret device and one in the smart pick. Both publish sensor events to an MQTT broker hosted alongside a Node-RED instance on an Azure VM. Node-RED performs the fusion logic, manages chord state, and serves the user-facing web dashboard.

Fret Device

  • SiWx917 Wi-Fi MCU
  • Addressable LED strip driven over SPI
  • I²S microphone for audio detection
  • OTA firmware update support

Smart Pick

  • SiWx917 Wi-Fi MCU
  • IMU read over I²C via QWIIC connector
  • Wrist-worn enclosure
  • Publishes strum motion events

Backend

  • Node-RED on Azure VM
  • MQTT broker for device telemetry
  • Sensor fusion with 500 ms window
  • Web dashboard for control and state
03

Hardware

The fret device PCB was designed in Altium around the SiWx917 module, with attention given to power distribution, decoupling, and impedance-controlled routing for the Wi-Fi traces. The board integrates a microphone for audio detection, headers for the LED strip's SPI interface, and a QWIIC connector for I²C peripherals. Power delivery worked reliably across the full build with no observed brownouts or rail issues.

During bring-up, the custom board exhibited a persistent Timeout 102 error during SWD programming that could not be resolved through jumper, pull-up, or POC reconfiguration. To preserve schedule, firmware was migrated to the SiWx917 development boards while the standalone PCB remained as a hardware deliverable. The microphone footprint was identified as a layout error during this process and is documented as a fix for any future revision.

04

Software

Three peripheral drivers were written for the SiWx917. The I²S driver configures the peripheral in receive mode at the microphone's word size and sample rate, with DMA-backed buffers feeding a frequency analysis routine that detects the presence of guitar audio. The I²C driver implements register-level read and write transactions for IMU initialization and polled accelerometer reads. The LED strip is driven over SPI by encoding the protocol's pulse timing directly into the MOSI bit pattern, eliminating the need for bit-banged GPIO timing.

The Node-RED backend subscribes to MQTT topics from both devices and applies a 500 ms correlation window: a chord advances only when an IMU strum event and a mic audio event arrive within that window, filtering out incidental motion and ambient noise. The dashboard exposes chord selection, mode toggling, tempo, and capo controls, and reflects the current chord state back to the fret device for LED rendering. The fret device firmware also supports OTA updates, with images hosted on the same Azure VM as the backend.
